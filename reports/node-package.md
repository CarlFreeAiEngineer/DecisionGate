# Node.js component verification

Implemented in `javascript/`: a Node-API 8 addon calls the existing C ABI on asynchronous native work, with an ordinary Promise API for JavaScript and TypeScript. ESM and CommonJS exports share one lazy session. The request queue is bounded at 64, failures reject with typed errors, initialization can retry, and native libraries remain pinned until process exit.

Verified on Apple silicon macOS with Node 24.14.0 and Node 26.7.0. Six tests cover concurrent first use, event-loop responsiveness, inclusive thresholds, criteria, Unicode, invalid input, excessive token length, bounded queue, direct addon argument validation, and three concurrent worker environments with clean exits. A separate forced worker termination during startup completed without a crash; normal applications should await calls before terminating workers.

The appointment reference returns `0.966611187427822`, exactly matching the Python wrapper over the same native release. No training or artifact changes were made.

The fresh consumer test installs the local tarball offline, compiles its TypeScript example, imports through ESM and CommonJS, changes working directory to `/`, and successfully retries after a deliberately missing packaged manifest. On macOS it runs with network access and reads of the original release/development native bundles denied by the OS sandbox. It exits normally. Run `node javascript/test/consumer.mjs` after packaging to repeat it.

Build with `npm ci`, `npm run build`, `npm test`, and `npm run pack:release` in `javascript/`. Release tarballs and SHA-256 files are named by platform in `released/node/`. The browser subpath is staged from `released/web/` when available; browser verification is recorded separately. Native and browser assets currently duplicate weights inside the combined tarball, making it about 627 MB compressed. This is a local distribution artifact, not a published npm package.

Linux x64 packaging and all six addon tests now pass on emeraldslate (Node 26.7.0, glibc 2.44). Its fresh package consumer also passes inside a Linux network namespace with only loopback, confirming inference and initialization retry without external networking. Its appointment result is 0.9666111806483961, differing from the Mac result by about 6.8e-9. See `node-consumer-linux-x64.json` and `remote-packages-linux-x64.json`. Node ABI stability is not a substitute for those tests. Consumers need no compiler; build machines need C++17, Node headers, and Windows also needs the matching `node.lib` with a Visual Studio developer shell.

Windows 11 x64 (build 26200) passes all six addon tests with Node 24.19.0 and the installed tarball consumer, including TypeScript compilation, ESM/CommonJS, browser subpath import, initialization retry, and clean exit. Its appointment result matches Linux exactly. See `node-consumer-windows-x64.json` and `remote-packages-windows-x64.json`. This consumer test did not block networking; Windows network-denial verification is recorded separately for the native C host. The MSVC addon build keeps its generated import library outside the native bundle so it cannot overwrite `decisiongator.lib`.
